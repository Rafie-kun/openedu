## What works today

- Accounts: email and password, scrypt hashing, database-backed sessions, login lockout, rate limiting,
  password change, immediate account deletion, JSON export.
- Profile: nationality, residence, intended degree level and subject, financial need band, preferred
  destinations, completeness scoring with named gaps.
- Qualifications: add and delete qualifications with an awarding body, grade scale, status, session,
  overall grade and up to 40 subject results marked achieved, predicted or estimated. Language tests with
  expiry.
- Catalogue: university, programme and scholarship lists with search, country, level and type filters,
  pagination, and verification badges with source links. Detail pages render requirements one by one.
- Eligibility: per-programme and per-scholarship evaluation with met, unmet, unknown and
  needs-confirmation groups, evidence strings, next steps, and a disclaimer on every result.
- Workspace: save and unsave universities, programmes and scholarships; application tracker with eleven
  statuses, status history, private notes, tasks with due dates and completion, a document checklist of
  labels and readiness, fee and deadline. `/calendar` merges your deadlines and open tasks with
  programme and scholarship deadlines, and each catalogue date keeps its verification badge.
- Budget: plans and cost items in a three-letter currency code, manual amounts, copy a recorded
  `CostEstimate` into a plan. Totals are shown in another currency using Frankfurter reference rates,
  with the source, rate date and a stale marker. A conversion is labelled an estimate.
- Assistant: `/assistant` posts to `api/assistant`, which retrieves up to ten catalogue rows, numbers
  them, and stores the reply with its citations. Your academic summary is opt-in per message and
  documents are never sent. Without a key the route answers 503 and the page stays read-only.
- Operations: `/api/health` reporting database reachability and which optional integrations are
  configured; audit log for account, academic, application, budget and assistant activity.
- Admin catalogue: `/admin/catalogue` adds a programme under an existing institution, or a scholarship
  and its provider, from an official URL plus the source page that was checked. Records start
  `PENDING_REVIEW`; marking one checked sets `lastCheckedAt`, writes a `VerificationRecord` and an audit
  entry, and archiving removes it from listings.
- Admin record detail (`/admin/catalogue/programme/[id]` and `.../scholarship/[id]`): each requirement,
  language condition, tuition fee, eligibility rule, funding component and deadline is added as its own
  row with its own source URL. Requirement, fee and deadline rows also start `PENDING_REVIEW` and are
  checked individually, so the engine compares a verified condition rather than a whole record's badge.
  Funding components now carry the same `sourceUrl`/`verificationStatus`/`lastCheckedAt` evidence as every
  other child row (previously only `isSpecified`, which records whether the provider states them at all —
  that field stays, it answers a different question). `adminVerificationSchema`'s entity allowlist now
  matches exactly what `applyCatalogueVerification` handles (the stray `University`/`VisaCategory` entries
  it previously carried with no matching case are gone).
  Archiving a child row drops it from the public programme/scholarship page and from the matching engine's
  input in the same way archiving the parent does; it still shows in the admin record view for history.
- Ingestion: `workers/data-ingestion` CLI runs the ROR or OpenAlex source adapter, writes `SourceRecord`
  rows with a version and change log, opens a `ReviewQueueItem` for new institution candidates, and
  records the run on `DataSource`/`IngestionRun`. `/admin/review` lists open items, shows the source
  payload and field changes, and lets an admin promote a candidate into `University` (unverified, source
  link attached), resolve, or reject.

## Known gaps

| Gap                                     | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin application                       | `/admin` lives inside `apps/web`, not a separate `apps/admin` workspace; there is no role-gated separate deployment. Covers the review queue, source registry, programme/scholarship entry and their child rows. Rows can be created and marked checked but not edited or deleted, and visa records have no editor                                                                                                                                                                                                                        |
| Python ingestion workers                | ROR, OpenAlex and SOMNIA_LEGACY adapters exist; no scheduler, no Redis queue, and retries are per-request, not across failed jobs. The Somnia adapter ran for real against the live legacy file and a local Postgres: 61 unique institution-identity candidates opened as `UNIVERSITY_CANDIDATE` review items (confirmed idempotent on a second run), 9 of which already match an existing OpenEdu university by name — none reviewed or promoted yet                                                                                     |
| Document upload and storage             | No upload route and no storage client. `ApplicationDocument.storageKey` is never set                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Email delivery                          | `EMAIL_PROVIDER_API_KEY` and `EMAIL_FROM` are validated but no provider is implemented                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Notification generation                 | The list, read state and preferences work; nothing creates a `Notification` row                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Assistant answer quality                | Retrieval is a keyword `contains` query over three tables, so a broad question retrieves thin context. No eval set and no per-conversation history: each profile keeps one thread                                                                                                                                                                                                                                                                                                                                                         |
| Verified visa records                   | `/visas` renders an empty state by design. No `VisaCategory` row exists                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Match persistence                       | Done. `lib/eligibility.ts` writes a `MatchResult` row plus `MatchRequirementResult` rows (one per requirement) on every evaluation, inside a transaction. History accumulates; nothing prunes it yet. `MatchingRuleVersion` stays unused — the engine has no versioned rule table to point at yet, only its own semver string                                                                                                                                                                                                             |
| Exchange-rate coverage                  | `SUPPORTED_CURRENCIES` is a hardcoded list and rates refresh only when a budget page is viewed. No background refresh and no rate for currencies outside the ECB set                                                                                                                                                                                                                                                                                                                                                                      |
| Programme and scholarship data          | `prisma/seed.ts` seeds 3 real programmes (Łódź Business Management, UCSI Foundation in Arts, Ravensbourne BSc Business Management with International Year One) and 2 real scholarships (UoPeople Scholarships, Romania MFA non-EU), each with real child records and the source page every fact came from, collected 2026-11-06. All start `PENDING_REVIEW`, not `VERIFIED`. Confirmed on 2026-11-08 with a real `prisma migrate deploy` + `pnpm db:seed` (twice, idempotent) against a live Postgres container. A pilot, not a catalogue |
| Programme and scholarship search        | Uses Prisma `contains`; only universities have full-text search and a GIN index                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Country directory                       | All 198 ISO 3166-1 countries are seeded as reference rows (codes, name, region only), but there is no route or education-system content. Countries appear only as filter options                                                                                                                                                                                                                                                                                                                                                          |
| CSRF and CSP                            | No explicit CSRF token and no Content-Security-Policy (`docs/security.md`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Email verification, password reset, 2FA | Not implemented                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Test coverage                           | Unit tests cover the engine, validation, candidates, the Gemini client and rate conversion. No route or component tests, and no Playwright config or `e2e` directory                                                                                                                                                                                                                                                                                                                                                                      |
| Accessibility and backups               | WCAG 2.2 AA has not been audited; backup and restore are undocumented and unmanaged                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

The GIN index on university full-text search **does** exist, in migration
`20261103093000_university_search_index`, and matches the expression in `apps/web/lib/search.ts`. The
remaining search limitation is that the query also matches `Country.name` with `ILIKE`, which the index
cannot serve.

## Next steps

1. Grow the real, sourced programme/scholarship pilot (3 programmes, 2 scholarships today) into an actually
   useful catalogue. Each new entry still needs the same live-page verification used for the first five —
   either an admin reads an official page directly, or another tool transcribes exact facts with their
   source URL for the admin to enter (see `docs/data-sources.md`). Have an admin move the seeded pilot
   rows from `PENDING_REVIEW` to `VERIFIED` or correct them against the live pages.
2. A scheduler and Redis-backed queue instead of manual CLI invocation, and a source adapter for a
   scholarship or visa portal now that two institution-candidate sources confirm the pipeline shape.
3. Notification generation for deadlines and data changes, with the dedupe key already in the schema.
4. Document upload with the storage controls listed in `docs/security.md`.
5. Email verification and password reset, both of which need an email provider.
6. Accessibility pass, Playwright coverage of the register-to-tracker journey (including the calendar
   and assistant), and a documented backup and restore procedure.
